# Running a VCPE game on the PSP-1000 (32 MB)

A PSP-1000 gives a homebrew game about 20-21 MB of heap (PPSSPP: 21.5 MB with `PSP_HEAP_SIZE_KB(-1024)`), against
about 50 MB on the 64 MB models. Most demakes are built to load everything once at boot. To fit a PSP-1000, keep
only the current level's content in memory and load the next behind the loading screen.

## Steps
1. **Measure first.** Run the game's scenarios in the emulator as a PSP-1000. The PPSSPP headless build in
   `.emu` reads `PPSSPP_PSP1000=1` (the regression script passes it through), and the log
   shows where it breaks. Print `vcpe_mem_used_kb()`, `vcpe_mem_peak_kb()` and `vcpe_heap_kb()` (the largest free
   block) in autotest builds.
2. **Split the content per level.** Make one resident "common" bundle with what every level uses, and one bundle
   per level with the rest. The converter decides this (for example: the common set is the intersection
   of what every scene uses; a sprite that several scenes use is duplicated into each scene's bundle).
3. **One block for the level bundles.** On a 32 MB console, call `vcpe_bundle_slab(first_level_bundle,
   last_level_bundle)` before the big boot loads. Loading a level bundle then reuses that block, so the heap cannot
   fragment.
4. **The volatile partition** (4 MB on every model): `vcpe_volatile_mem(&size)`, then
   `vcpe_bundle_load_at(common, mem, size, 1)` when the common bundle fits. Only data that can be read again
   belongs there, because it is reloaded after sleep.
5. **Loading screen around every swap:**
   ```c
   vcpe_loading_begin(level_bundle_size + level_data_size);
   free_level(); load_level(n);          /* PAK reads move the bar */
   vcpe_loading_end();
   ```
   Call it between frames. With pipelining on, a game that frees memory the GE may still read (its own textures,
   fonts) calls `vcpe_gfx_gpu_wait()` first.
6. **Refuse what still does not fit, readably.** If a level's content cannot load, show `vcpe_fatal` with the
   free memory. Never draw a level without its textures. A game that cannot be made to fit keeps
   `vcpe_require_64mb`.
7. **Check the 64 MB build stays frame-identical** (the frame-recording regression), and play it on a real
   PSP-1000. The emulator does not model CFW plugins, which take memory, and it does not model sleep.

## What doesn't help much
- Streaming sound effects. They are small next to textures, and a missing sound is worse than a loading screen.
- `PSP_HEAP_SIZE_KB` closer to the limit. Thread stacks and file buffers need the last megabyte.
